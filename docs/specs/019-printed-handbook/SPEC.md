# SPEC: The printed D&D handbook

## Summary

The eight `dnd/` house-rule pages are rendered as one A4 PDF, one fixed-size sheet
per page, generated by a dev-time command and committed to the site so a reader can
download it from its own URL. The PDF is a vector file with embedded fonts and
selectable text, it is produced by a browser without that browser entering the
build, and it comes with one PNG per sheet taken from the same DOM through the same
stylesheet so the image is evidence about the artifact rather than a second
opinion about it. A committed manifest makes the artifact fail rather than go
stale when the content changes underneath it.

## Problem Statement

The house rules are the reason this site exists, and they exist only as eight web
pages. At the table they are a phone, a browser and a search box, which is the
worst possible shape for the one thing a player reaches for mid-turn: a weapon
property, a magic fix, an injury rule. The content is already written, already
structured and already styled as a rulebook. What is missing is the book.

Producing it is not a formatting problem, it is three problems wearing one.

**The content is a website, and a book is a different medium.** A page scrolls; a
sheet does not. Eight pages of reference tables and short rules have to become
fixed-size sheets with page numbers, a contents and a cover, and every rule has to
land somewhere a reader can predict. Nothing on the site today knows what a sheet
is, and no layout on the site today is measured in millimetres.

**Rendering it needs a browser, and three accepted ADRs say the browser may not
be a dependency.** [ADR-0007](docs/adr/0007-mermaid-rendering-strategy.md) chose
`astro-mermaid` precisely so no headless browser is needed to build the site.
[ADR-0011](docs/adr/0011-headless-browser-mcp-server.md) keeps the browser behind
a pinned local MCP server and out of the manifest entirely.
[ADR-0012](docs/adr/0012-dependency-free-cdp-capture-client.md) then owns the
captures with a dependency-free CDP client and forbids a second browser stack and
a second dev-server lifecycle. A handbook is a browser-driven artifact produced
inside those constraints, not outside them.

**The site's heading metrics are not deterministic.** The display face arrives
from a third-party CDN with a `swap` display policy and falls back silently to
Bookinsanity, a different typeface with different advances. Nothing errors and
nothing warns. A handbook that paginates differently on two machines is not a
book, and this failure would be invisible in the artifact. That is
[ADR-0019](docs/adr/0019-self-host-cinzel.md), and it lands first because it is
correct for the site whether or not the handbook ever exists.

The staleness problem is the fourth, and it is the one that decides whether the
other three were worth doing. Edit a house rule, and a committed PDF keeps saying
the old thing with nothing failing. A generated artifact that is committed
without a gate against it is worse than no artifact, because it is confidently
wrong.

## Goals

- The eight house-rule pages are printable as one A4 PDF with the site's own
  fonts, colours and styling, and no site chrome.
- The artifact is generated by a dev-time command and committed, so a reader can
  download a file rather than print from their own browser.
- The PDF is a single vector file: real embedded fonts, selectable and searchable
  text.
- No browser enters the build. `package.json`, `pnpm-lock.yaml` and
  `pnpm-workspace.yaml` are untouched by the whole feature.
- The generator reuses the existing browser session, browser-resolution order,
  font gate and dev-server boundary rather than adding a second copy of each.
- Each sheet is also captured as one PNG at an exact raster size, from the same
  DOM and the same stylesheet as the PDF.
- Every place the generator decides where a page ends is named in its output and
  recorded in the artifact's record, and authored breaks eventually replace all of
  them.
- A committed manifest fails the test suite when the source content changes
  without the artifact being regenerated.
- Heading metrics are identical on every machine, because the display face is
  served from the repository.
- The handbook has a cover, a contents with real page numbers, and a publisher
  page that carries its version and its edition date.
- A horizontal rule in a house-rule page means "start a new sheet", and that
  meaning is identical on the website and in the artifact.

## Non-Goals

- A PDF as the primary way to read the house rules. The web pages remain the
  canonical source and are never replaced.
- Print-from-the-browser as a fallback. It is not offered, because offering it
  implies the artifact is equivalent when it is not.
- Any content authored for print only. Every rule in the artifact already exists
  on a page.
- Editing or proofing tools, annotations, forms, signatures, and any fillable
  field.
- A change to the index page. It is contractually free of action buttons and this
  feature does not reverse that.
- Full-resolution golden PNGs in version control. Image comparison is a local
  opt-in mode against a baseline held outside the repository.
- Optimising the artifact for file size beyond what the vector requirement
  demands.

## User Stories

1. As a player at the table, I want the house rules as one downloadable PDF, so
   that I am not looking things up on a phone mid-turn.
2. As a player, I want the text in the PDF to be selectable and searchable, so that
   I can find a rule the way I find it on the site.
3. As a player, I want the handbook to look like the site, so that a rule does not
   read differently because of the medium it arrived in.
4. As a player, I want no site sidebar, table of contents or navigation in the
   artifact, so that a printed page is the rule and nothing else.
5. As a player, I want each source page to start on a fresh sheet, so that the
   book reads as eight chapters and I can find one by remembering where it begins.
6. As a player, I want the contents to list the eight source pages with real page
   numbers, so that the contents sends me to the right place.
7. As a player, I want a page number in each sheet's footer, so that I can say
   "turn to twenty-two" and mean it.
8. As a player, I want wide tables to span the full sheet rather than be clipped
   or squeezed, so that the reference pages are usable in print.
9. As a player on a phone at the table, I want the handbook to be reachable from
   any page of the site, so that I do not have to navigate to the homepage first.
10. As a player, I want the download page to state the handbook's version and
    edition date, so that I know which edition I am holding.
11. As a player, I want the artifact to carry a sheet I can visually scan, so that
    a glance replaces a search.
12. As a maintainer, I want the artifact to fail loudly when the content changes
    without a regeneration, so that no reader ever downloads a stale book.
13. As a maintainer, I want every automatic split named in the generator's output
    and in the manifest, so that no machine decides silently where a rule lands.
14. As a maintainer, I want the author's own `hr` to eventually replace every
    automatic split, so that pagination becomes authored rather than inferred.
15. As a maintainer, I want a horizontal rule to mean "new sheet" on the website
    as visibly as it does in print, so that a divider never means something in one
    medium and nothing in the other.
16. As a maintainer, I want the generator to reuse the existing browser tooling,
    so that there is one browser stack to reason about and one to keep current.
17. As a maintainer, I want the generator to refuse to write anything when the
    display font has not genuinely loaded, so that a silent fallback never becomes
    a committed artifact.
18. As a maintainer, I want the generator to fail with the documented dev-server
    command rather than start a server of its own, so that there is one server
    lifecycle in this project.
19. As a maintainer, I want every written file validated by reading it back, so
    that a truncated PDF is a failure rather than a shipped file.
20. As a maintainer, I want the font served from the repository, so that a
    rendering on my machine and a rendering on a reader's machine are the same
    layout.

## Implementation Plan

The feature is five tickets in a strict order. Each is a tracer bullet for the
one after it, and the order is not negotiable because each one removes an unknown
from the next.

### Step 1: Self-host Cinzel (#419)

Prerequisite, and independent of everything after it. Cinzel 400 and 700 move
into `public/fonts/` beside Bookinsanity and ScalySans, declared from the site's
own stylesheet and preloaded; the three Google Fonts tags leave the head; the font
licensing record states the OFL 1.1 attribution obligation that vendoring creates.

This is [ADR-0019](docs/adr/0019-self-host-cinzel.md) and it lands first because
the spike in Step 2 has a font gate, and a gate that can be satisfied or defeated
by whether a CDN answered is not a gate.

### Step 2: A vector PDF of fixed-size sheets (#420)

The tracer bullet, and it deliberately delivers a plain single-column footer-less
PDF. What it proves is that a browser-driven render can produce a correct
multi-sheet PDF while keeping ADR-0007, ADR-0011 and ADR-0012 intact.

The mechanism is the **sheet box**: a print route renders the eight `dnd/` pages
in sidebar order, which is title-ascending, matching the autogenerated sidebar
group. Each sheet is a fixed-height box exactly the size of the page content area
with a break after it. Geometry, stated once:

| Property | Value |
|----------|-------|
| Page | A4, 210 x 297mm |
| Margins | 25mm top and left, 15mm right and bottom |
| Sheet box | 643 x 972 CSS px |

The route ships **no** client-side JavaScript. Sheet assignment is injected at
runtime by the command, through the same document-start mechanism the capture
command already uses to seed the theme before first paint, so the committed route
is inert HTML.

**The spike runs before any real content is rendered.** Print a two-sheet fixture
and read back the actual page count and the actual sheet boxes from the written
file. The open question is whether page-size and break rules still paginate when
the page is emulated as screen media rather than print media. It matters because
Starlight's own print stylesheet re-declares the colour ramp to a cool blue at hue
224, and the warm bark ramp survives today only because the site's stylesheet loads
later in the cascade; if print media is required, that ordering becomes
load-bearing in a second place. The result is recorded in
[ADR-0020](docs/adr/0020-sheet-box-renderer.md) and the ADR moves to `accepted`.

### Step 3: Two columns, per-sheet PNGs and a footer (#421)

Sheets become two 306px columns with a 30px gutter, because a single 643px
measure at 16px is a very long line for a page read at a table and two 306px
columns read like a printed rulebook. Anything wider than its column spans both
columns automatically, which makes wide tables the expected case rather than the
exception.

The opt-out key needs care. The docs collection uses Starlight's default schema,
a Zod object in strip mode, so an unknown key parses fine, appears in the file and
is `undefined` at render time with nothing indicating why. Reading a per-page
column count requires extending the schema through the documented `extend` option
rather than adding a bare key.

Each sheet's footer carries the source page title and the current section name on
the left, a decorative rule in the centre and the page number on the right. Page
numbers read `12 of 48` rather than a bare number, which is free once the sheet
count is known. Each sheet also gets one PNG at exactly 1588 x 2246, with the
vertical raster scale a flag defaulting to 2, validated by reading back the PNG
header rather than trusting the write. The PNG and the PDF come from the same
stylesheet and the same DOM, so they cannot disagree about layout.

The parchment background and the footer ornament are generated once and committed
at single documented paths, the ornament from the existing gold-rule colour token
so it belongs to the site's rule vocabulary rather than being an unrelated
drawing. Contrast on the generated parchment is **measured** with the existing
contrast command against the existing threshold, because a decorative background
behind body text is exactly where contrast quietly goes.

### Step 4: The split report and the manifest (#422)

Content that does not fit a sheet is split at the nearest block boundary, never
clipped, and **every split is printed by name and recorded**. A generator that
quietly decides where a page ends is a generator that can quietly change which
page a rule appears on, with nothing saying so.

The **manifest** is a small committed file carrying a content hash of the eight
sources, the sheet count, and each sheet's page number and text hash. It is the
primary regression gate: a few kilobytes, reviewable in a diff, and it catches the
failure that actually happens, which is content changing while the artifact did
not. The hash is content-based and never a timestamp, so it survives a clone, a
rebase and a fresh checkout on another machine.

Two tests follow from it: one fails when the manifest's source hash no longer
matches the current content, and one fails while any split remains recorded, so
authored breaks win over automatic ones over time without anyone being blocked
from producing the artifact on day one. The written manifest is validated by
reading it back, so a truncated file is a failure rather than a passing test
against an empty object.

Full-resolution golden PNGs stay out of version control. At the chosen raster
scale one sheet is several hundred kilobytes and the book runs to dozens of
sheets, which is tens of megabytes of binary in a repository that is otherwise
text. Image comparison is an opt-in local mode against a baseline held outside
version control, and it is described honestly as corroboration rather than ground
truth.

### Step 5: Cover, contents and a publisher page (#423)

A cover sheet carries the handbook title, version and edition date. A contents
sheet lists the **eight source pages only**, not their section headings, because
forty sub-entries on one two-column sheet is a wall and the page number per source
page is the thing that sends a reader to a page.

Page numbers do not exist until layout has run, so **the same single layout pass
that assigns content to sheets also fills the contents and stamps the page
numbers**. The site build does not run twice, and the committed artifacts come
from one render.

The publisher page lives at its own URL, outside the house-rule pages so it is not
printed into itself, and carries the version, the edition date and a plain
download link. It is reachable through a fourth sidebar group, which makes it
discoverable from every page rather than only from the homepage, and it is what
makes the artifact documented rather than merely linked. The index page is
untouched: no `LinkButton`, no action row, no download affordance.

**The sheet-break authoring rule.** A horizontal rule in the house-rule pages
means "start a new sheet", and one rule makes it safe by blocking two distinct
hazards. In CommonMark, a rule on the line immediately after paragraph text is a
setext heading level two rather than a rule. And the weapon-properties test's
markdown table reader treats a lone `---` as a table separator, so a rule placed
immediately after a table's last data row silently deletes that row and fails four
assertions. Requiring a blank line above the rule makes both parsers skip it
safely. The rule is asserted by a test and documented in the writing-style
section of `AGENTS.md`.

## ADR Constraints

Only accepted ADRs bind, and all four of these do:

| ADR | Title | Constraint |
|-----|-------|------------|
| 0007 | Render Mermaid Diagrams with the astro-mermaid Integration | Chosen so no headless browser is needed to build the site. The handbook does not reopen it: no browser enters the build. |
| 0011 | Give Agents a Headless Browser via a Pinned Local MCP Server | The browser stays behind the local MCP server and out of the manifest. `git diff -- package.json pnpm-lock.yaml pnpm-workspace.yaml` must be empty across this whole feature. |
| 0012 | Own the Design Review Captures with a Dependency-Free CDP Client | One browser stack, one browser-resolution order, one font gate, one `--start-dev-server` boundary. The generator reuses them and duplicates none of them. |
| 0019 | Self-Host Cinzel so Heading Metrics Are Deterministic | The display face is served from the repository, so a rendering does not depend on a third party. The font gate is a refusal, not a warning. |

[ADR-0020](docs/adr/0020-sheet-box-renderer.md) is `proposed` and is therefore not
a constraint on the implementation. It is the record this spec expects to exist,
and the spike in Step 2 is what moves it to `accepted`.

## Testing

The seams here are the artifact's own file formats, because that is where a bug in
a PDF is visible at all. Nothing in this feature is tested by asserting on the
generator's internals.

- **The written PDF is read back.** PDF magic, end-of-file trailer and the real
  page count. A file that is absent, empty, truncated or the wrong length is a
  failure, not a warning. This is the primary seam for Step 2 and it is a seam
  that cannot be faked, because the bytes either say what they should or do not.
- **The written PNG header is read back**, for the exact raster size rather than
  trusting the write, and for the same reason.
- **The font gate refuses.** If the display face is not genuinely loaded the
  command exits non-zero, names the font and writes nothing. This is asserted
  against a simulated CDN outage rather than argued about.
- **The manifest is a test.** Source hash mismatch fails, and any recorded split
  fails. The manifest is validated by reading it back rather than parsed from a
  string in the same process that wrote it.
- **The two parsers that break on a rule are asserted directly**: a test asserts
  every horizontal rule in the house-rule pages has a blank line above it, and the
  weapon-properties table reader is the reason that test exists.
- **Contrast on the generated parchment is measured**, with the existing contrast
  command against the existing threshold, because a decorative background behind
  body text is where contrast quietly goes.
- **The boundary is asserted by diff.** The manifest files come back empty across
  the feature, which is ADR-0011's acceptance condition stated as a check.
- **One golden PNG is a human check, not a test.** The spike's two-sheet fixture
  is read back for its page count and sheet boxes, and the result is recorded in
  ADR-0020 rather than in a snapshot.

## Rollback

Each step is independently reversible, and the order means a rollback never
strands a later step.

- Steps 4 and 5 are reversible by deleting the committed artifact, its PNGs and
  its manifest, which leaves the site exactly as it was. Nothing else in the
  feature depends on them.
- Step 3's per-sheet PNGs, footer, columns and generated artwork are all
  disposable files plus a stylesheet section. Removing them leaves a working
  single-column PDF from Step 2.
- Step 2 is reversible by removing the print route and the generator command. The
  cost of rolling it back is the spike result, so it is recorded in ADR-0020 before
  any real content is rendered.
- Step 1 is reversible on its own, and should not be rolled back by accident: it
  is a correct improvement to the site independent of the handbook, and
  un-vendoring the face would churn the font path across every page.

## Further Notes

- The manifest diff is the review artefact this feature produces. A reviewer
  reading a change to a house rule sees the rule's diff and the manifest's diff
  together, which is how a reader learns the artifact is not allowed to drift.
- The folio vocabulary note matters more here than it looks. The index page's
  `folio` is a contents-entry number and is not a print folio; the number printed
  in a sheet footer is a page number. The existing index usage is left alone,
  because renaming a tested model for no functional gain is a cost with no
  benefit.
- The artifact is a committed binary in an otherwise text repository. That is a
  deliberate trade: a downloadable handbook has to be in the tree for the publisher
  page to link to something stable. The manifest is what keeps that trade honest.
- Eight pages, one of which is thirty kilobytes, is a small book. It is also the
  worst realistic case for automatic splitting, which is why Step 4 exists rather
  than being deferred as a nicety.
