This page demonstrates the `XmlCard` component in its display modes and
configuration options. Unlike golden-forest's `XmlChar` (which takes a
`filename` and parses XML in the browser), `XmlCard` takes build-time parsed
`character` JSON - missing files therefore fail the build instead of
rendering an error card.

Card portraits link to character pages. A card whose character has a
`filename` wraps its portrait in an anchor to
`/fantasy-grounds/characters/<filename>` labelled `View <name> character
sheet`, so every card on this page opens a real character page. Pass
`link={false}` to render a plain portrait.

Character data comes from the single `src/generated/characters.json` build
artifact, read through the typed loader `src/utils/generated-characters.ts`
(look entries up by `filename`):

```mdx
import XmlCard from '@/components/xml-viewer/XmlCard.astro';
import { getCharacter } from '@/utils/generated-characters';

export const tanadirian = getCharacter('tanadirian');

<XmlCard character={tanadirian} display="small" />
```

## Display: Small

Compact card: name, race/class/level, alignment/background/deity, vitals grid,
compact abilities (MOD + SAVE). Avatar is the same size as medium/large (64px).
Small cards are `inline-block`, so they flow side by side.

## Display: Medium

Everything from small mode, plus the full ability grid, languages, feats and
proficiency bonus. Skills are the same table card the large display uses, holding
only the proficient ones, and Languages and Feats ride that same panel below it -
each an `h3` heading above one pill plate. This is the default size.

Medium does **not** show Saving Throws. A roster card is a glance, and the saving
throws are figures a reader computes with rather than recognises; the character
page and the large sheet print all six of them properly. Feats, the most
identifying thing on a D&D character, do show here.

Medium and large carry the same six **tabs** - Overview, Skills, Inventory,
Weapons, Features, Powers - and an entry appears only when the card has something
to put in it, so a character with no inventory has no Inventory entry. They differ
in which sections exist and which panel holds them, not only in what the bar does.
At medium it is a tab bar: clicking an entry opens that section and closes the
others. Switching changes nothing about a section's design - every panel is
rendered on the server and hidden with `x-show`, so a switch reveals rather than
reloads.

The Skills entry appears whenever the panel has anything in it, and at medium the
two pill sections count: a character with feats but no proficient skills still gets
a Skills tab, or the feats would have nowhere to render.

Keyboard: one Tab press enters the bar, the arrow keys and Home/End move between
tabs, and the selected tab is the bar's only tab stop.

## Display: Large

The complete card: the same six tabs as medium, with more in each. Subclass and
deity join the header, passive skills join the Overview panel, the all-skills table
lists every skill rather than the proficient ones, and all six saving throws are
shown beside the character. Languages and Feats stay in the Overview panel at
this size, after Saving Throws and in the same order as before. The display mode
is fixed at build time by the `display` prop the mounting page passes; there is no
in-card display-mode toggle.

At large the bar **jumps rather than hides**. Every section is rendered visible
and each entry is an anchor link to it, so the bar is a table of contents for a
page you are already scrolling, and it works with JavaScript disabled - no
`x-data`, no `x-show`. Nothing is marked selected, because nothing is hidden.

Each section also carries its own heading here - Skills, Inventory, Equipped
Weapons, Features, Powers - in the same micro-label style as Vitals, Saving
Throws, Languages and Feats. There is no tab naming the open section at this size,
so the heading is what tells you where you are on a long scroll, and it is what a
jump link lands on. Medium does not show those five: the tab is the name there.
Languages and Feats are the one pair that carries its heading at both sizes, at
`h3` either way, because neither panel holding them has a heading to sit beneath.
Inventory's heading carries its carried-weight total on the baseline.

### Section Menu and Responsive Behaviour

**The menu bar** is six entries on the card's own surface, flush against the header
above and the sheet below. It sits on one line when the card is wide enough for it
and wraps to two below 620px of *container* width, which is the width of a card in
the two-column party roster rather than the width of the window. It never scrolls: a
scrolling strip would hide two of six sections behind an edge most readers never
find. Each entry's 44px minimum height holds at every width, and the 8px
horizontal padding is there to keep the labels reading as one band, not to make
the target small.

**The Overview panel** splits only at `large`, and it is the only panel that
does: on card containers at least 72rem wide (`@6xl`) the character sits in the
left half and Saving Throws, Languages and Feats take the right. On containers at
least 80rem wide (`@7xl`), that right half splits again - Saving Throws left,
Languages and Feats stacked right - and only when they hold few enough pills to
fit. At medium the panel is a single column, because there is nothing that could
sit beside the character: Saving Throws is not rendered there and the pill
sections have moved to the Skills panel. Every other panel holds one section, so
there is nothing to put beside it and each is full width.

**The inventory and weapons tables** drop a column on a narrow card. Below `@lg`,
inventory folds Weight and State into a second line under the item name, and
weapons folds Properties under the weapon name; the attack bonus and the damage
column stay their own columns at every width, because those are the columns a
player reaches for mid-session.

The docs column here is narrower than the `@6xl` threshold, so the paired layout
never appears on this page - open the
[Akinori character sheet](/fantasy-grounds/characters/akinori) to see it at full
width (the portrait on that page links to the same URL). The
[current party page](/fantasy-grounds/current-party/) is where the narrow card
shows up: six cards in two columns, each with a wrapped tab bar.

## Notes

- **Powers:** parsed from the direct-child `<powers>` collection
  (`id-` keys, like every other Fantasy Grounds list); nested `<powers/>`
  inside inventory items is excluded. 108 of the 111 characters have at
  least one power.
- **Multiclass:** no character in the set currently has more than one
  class; the `Class A x / Class B y` rendering is untested against live
  data.
