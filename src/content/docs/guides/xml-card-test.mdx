This page demonstrates the `XmlCard` component in its display modes and
configuration options. Unlike golden-forest's `XmlChar` (which takes a
`filename` and parses XML in the browser), `XmlCard` takes build-time parsed
`character` JSON — missing files therefore fail the build instead of
rendering an error card.

Card portraits link to character pages. A card whose character has a
`filename` wraps its portrait in an anchor to
`/fantasy-grounds/characters/<filename>` labelled `View <name> character
sheet`, so every card on this page opens a real character page. Pass
`link={false}` to render a plain portrait.

Character data comes from the `src/generated/characters.json` build artifact
(a single array; look entries up by `filename`):

```mdx
import XmlCard from '@/components/xml-viewer/XmlCard.astro';
import characters from '@/generated/characters.json';

export const tanadirian = characters.find((c) => c.filename === 'tanadirian');

<XmlCard character={tanadirian} display="small" />
```

## Display: Small

Compact card: name, race/class/level, alignment/background/deity, vitals grid,
compact abilities (MOD + SAVE). Avatar is the same size as medium/large (64px).
Small cards are `inline-block`, so they flow side by side.

### Single Character


## Display: Large

The complete card: portrait (floated right), feats, features grouped by
level, and powers grouped by level and group. The display mode is fixed at
build time by the `display` prop the mounting page passes; there is no
in-card toggle.

### Passive Skills

Large mode adds a Passive Skills section between Abilities and Saving Throws.
The section renders no visible heading: hovering it reveals a "Passive Skills"
tooltip. It holds three subcards side by side, each a single row with the
name on the left and the value on the right: Passive Perception,
Passive Investigation, and Passive Insight. The subcards reuse the
vitals-item styling, including the same uniform `rounded-[7px]` radius on
all four corners. Tanadirian's parsed passives are 18 / 11 / 18. The section
renders only in large mode; small and medium cards omit it at build time.

```mdx
<XmlCard character={tanadirian} display="large" />
```

<XmlCard character={tanadirian} display="large" />

### All-Skills Table

Large mode replaces the prof-only skills grid with one card holding two
tables of every skill on the sheet, split alphabetically into halves. Each
row shows the skill name, its ability abbreviation, and the total
right-aligned in mono. Gold dots mark proficiency: one dot for proficient,
two for expertise, none for untrained, with a tooltip on each marker. Custom
skills take their ability from the sheet's `stat` field, so ethir's
`Thieves Tools (Traps)` row reads `INT`. Ethir has 20 skills - two dots
appear on `Sleight of Hand` and both `Thieves Tools` rows (expertise), one
dot on the proficient rows. Tanadirian has 18 skills with no expertise, so
he exercises the one-dot and no-dot cases. Medium cards render the prof-only
skills grid instead, and small cards omit the section entirely; the display
mode is fixed at build time, with no live switching.

```mdx
<XmlCard character={ethir} display="large" />
```

<XmlCard character={ethir} display="large" />


### Equipped Weapons

Large mode adds an Equipped Weapons table after Inventory and before Features, listing
only weapons the sheet marks as equipped (`carried` 2). Each row shows the
computed ATK, the weapon name, its properties (`-` when the sheet has none),
and the computed Damage. Alberich exercises the display: with STR 18 and a +2
proficiency bonus, his Greatsword reads ATK `+6` and damage `2d6+4 Slashing`,
and his two equipped Handaxes each read ATK `+6` and damage `d6+4 Slashing`.
Stowed or sold weapons are omitted, and the section disappears entirely when
nothing is equipped. Small and medium cards omit the section at build time.

```mdx
<XmlCard character={alberich} display="large" />
```

<XmlCard character={alberich} display="large" />

### Inventory

Large mode adds an Inventory section after Skills and before Equipped Weapons. A
muted line above the items table reads the carried weight total against the
5e carrying capacity of STR x 15; alberich (STR 18) reads
`68.0 / 270 lb. carried`. The table columns are Item, Count, Weight, and
State, listing every carried or equipped item (`carried` 1 or 2) in sheet
order with its name, count, unit weight to one decimal, and a plain-text
State of `Carried` or `Equipped`. Stowed or dropped items never appear.
Below it, a Current Wealth card shows the parsed coins in fixed order PP, GP,
EP, SP, CP. The section disappears entirely when nothing is carried and
every coin is zero. Small and medium cards omit the section at build time.

```mdx
<XmlCard character={alberich} display="large" />
```

<XmlCard character={alberich} display="large" />

### Saving Throws

Large mode replaces the prof-only saving-throw grid with one card holding two
tables of all six saves in standard ability order. Each table carries
`Ability` and `Save` headers; the first lists STR, DEX, and CON and the second
INT, WIS, and CHA. Each row shows the ability abbreviation and the signed
bonus right-aligned in mono; a proficient save carries a single gold dot with
a "Proficient" tooltip. Alberich exercises the display: STR `+6` and WIS `+5`
are proficient, while DEX `+2`, CON `+3`, INT `+1`, and CHA `+1` are not.
Medium cards render the prof-only saving-throw grid instead, and small cards
omit the section entirely; the display mode is fixed at build time, with no
live switching.

```mdx
<XmlCard character={alberich} display="large" />
```

<XmlCard character={alberich} display="large" />

### Languages

Medium and large cards render Languages as a single accent card instead of a
heading above a pill row: the uppercase "Languages" label sits on the left
and the language pills sit on the right, reusing the vitals-item shell with
the colored top line, border, and uniform `rounded-[7px]` radius. The pill
list wraps onto new lines when it exceeds the card width; on narrow
containers the label stacks above the pills, and they share one row at wider
container widths. Small cards omit the section at build time, with no live
switching.


### Overview Group

Large cards group Vitals, Abilities, and Passive Skills under one visible
`Overview` heading; small and medium cards render the same sections without
the heading. On card containers at least 72rem wide (`@6xl`), the Overview
group takes the left half of the card while Saving Throws, Languages, and
Feats stack in the right half; below that width the sections stack in a
single full-width column. The display mode and the grouping are fixed at
build time, with no live switching.

```mdx
<XmlCard character={alberich} display="large" />
```

<XmlCard character={alberich} display="large" />

### Ultra-Wide Section Pairings

At the same `@6xl` threshold, large cards pair the remaining sections into
halves: Saving Throws, Languages, and Feats stack in the right half beside
the Overview group; Skills sits beside Inventory and Current Wealth;
Equipped Weapons spans the full width; and Features sits beside Powers. When
a partner stack is empty (no saving throws, no languages, no feats, no
inventory contents, or no powers), the surviving section keeps the full
width. Paired sections drop their top rule at ultra-wide widths so both
columns start level, and everything stacks back into one full-width column
below 72rem. The pairing is fixed at build time, with no live switching.

```mdx
<XmlCard character={alberich} display="large" />
```

## Notes

- **Powers:** parsed from the direct-child `<powers>` collection
  (`id-` keys, like every other Fantasy Grounds list); nested `<powers/>`
  inside inventory items is excluded. 108 of the 111 characters have at
  least one power.
- **Multiclass:** no character in the set currently has more than one
  class; the `Class A x / Class B y` rendering is untested against live
  data.
