This page demonstrates the `XmlCard` component in its display modes and
configuration options. Unlike golden-forest's `XmlChar` (which takes a
`filename` and parses XML in the browser), `XmlCard` takes build-time parsed
`character` JSON — missing files therefore fail the build instead of
rendering an error card.

Character JSON is imported from the `src/generated/characters/` build artifacts:

```mdx
import XmlCard from '@/components/xml-viewer/XmlCard.astro';
import tanadirian from '@/generated/characters/tanadirian.json';

<XmlCard character={tanadirian} display="small" />
```

## Display: Small

Compact card: name, race/class/level, vitals grid, compact abilities
(MOD + SAVE). Small cards are `inline-block`, so they flow side by side.

### Single Character

```mdx
<XmlCard character={tanadirian} display="small" />
```

<XmlCard character={tanadirian} display="small" />

### Multiple Characters (Default Flow)

Small cards flow naturally side by side without any wrapper.

```mdx
<XmlCard character={murky} display="small" />
<XmlCard character={malfunction} display="small" />
```

<XmlCard character={murky} display="small" />
<XmlCard character={malfunction} display="small" />

### Multiple Characters (Centered)

Wrap them in a centered container.

```mdx
<div style={{ textAlign: 'center' }}>
  <XmlCard character={delizan} display="small" />
  <XmlCard character={dorian} display="small" />
  <XmlCard character={dougal} display="small" />
</div>
```

<div style={{ textAlign: 'center' }}>
  <XmlCard character={delizan} display="small" />
  <XmlCard character={dorian} display="small" />
  <XmlCard character={dougal} display="small" />
</div>

grid, proficient-only saving throws, skills, languages, and proficiency

## Display: Large

The complete card: portrait (floated right), feats, features grouped by
level, and powers grouped by level and group. Includes S/M/L toggle buttons
to switch display modes live.

### Fallback Portrait

Garaele has no avatar file, so the build-time probe falls back to
`faceless.svg`. Forcing a non-existing `image` resolves to the same
fallback at build time.

```mdx
<XmlCard character={garaele} image="dontexists.jpg" display="large" />
```

<XmlCard character={garaele} image="dontexists.jpg" display="large" />

```mdx
<XmlCard character={garaele} display="large" />
```

<XmlCard character={garaele} display="large" />

### Default Portrait (JPG, by Filename)

Milo relies on the default naming convention: no `image` prop, so the
portrait resolves from the XML filename (`milo.xml` → `milo.jpg`).

```mdx

<XmlCard character={milo} display="large" />
```

## Notes

- **Powers:** none of the 111 characters in the current export set has
  direct-child `<powers>`, so the Powers section stays hidden everywhere.
  It renders once the source data contains powers.
- **Multiclass:** no character in the set currently has more than one
  class; the `Class A x / Class B y` rendering is untested against live
  data.
