This page demonstrates the `XmlCard` component in its display modes and
configuration options. Unlike golden-forest's `XmlChar` (which takes a
`filename` and parses XML in the browser), `XmlCard` takes build-time parsed
`character` JSON - missing files therefore fail the build instead of
rendering an error card.

Card portraits link to character pages. A card whose character has a
`filename` wraps its portrait in an anchor to
`/fantasy-grounds/characters/<filename>` labelled `View <name> character
sheet`, so every card on this page opens a real character page. Pass
`link={false}` to render a plain portrait.

Character data comes from the single `src/generated/characters.json` build
artifact, read through the typed loader `src/utils/generated-characters.ts`
(look entries up by `filename`):

```mdx
import XmlCard from '@/components/xml-viewer/XmlCard.astro';
import { getCharacter } from '@/utils/generated-characters';

export const tanadirian = getCharacter('tanadirian');

<XmlCard character={tanadirian} display="small" />
```

## Display: Small

Compact card: name, race/class/level, alignment/background/deity, vitals grid,
compact abilities (MOD + SAVE). Avatar is the same size as medium/large (64px).
Small cards are `inline-block`, so they flow side by side.

### Single Character

```mdx
<XmlCard character={tanadirian} display="small" />
```

Small cards flow naturally side by side without any wrapper.

## Display: Large

The complete card: portrait (floated right), subclass, feats, features grouped
by level, powers grouped by level and group, passive skills, the full
all-skills table, equipped weapons, inventory with current wealth, all six
saving throws, and the Overview group. The display mode is fixed at build time
by the `display` prop the mounting page passes; there is no in-card toggle.

The complete card uses Akinori below; four terse edge-case cards follow for
what Akinori cannot show.

### Ultra-Wide Layout

On card containers at least 72rem wide (`@6xl`), large cards pair their
sections into two columns: the Overview group sits beside Saving Throws,
Languages, and Feats; Skills sits beside Inventory and Current Wealth;
Equipped Weapons spans the full width; and Features sits beside Powers. On
containers at least 80rem wide (`@7xl`), the Saving Throws group splits
again: Saving Throws takes the left half while Languages and Feats stack in
the right half. That extra split only happens when Languages and Feats hold
few enough pills to fit, otherwise the group stays in a single column. Below
72rem the sections stack in a single full-width column. The docs column here
is narrower than that threshold, so the paired layout never appears on this
page - open the [Akinori character sheet](/fantasy-grounds/characters/akinori)
to see it at full width (the portrait on that page links to the same URL).

## Notes

- **Powers:** parsed from the direct-child `<powers>` collection
  (`id-` keys, like every other Fantasy Grounds list); nested `<powers/>`
  inside inventory items is excluded. 108 of the 111 characters have at
  least one power.
- **Multiclass:** no character in the set currently has more than one
  class; the `Class A x / Class B y` rendering is untested against live
  data.
